# Phase 03 parameterized validation cases

Unseen inputs for the computational problems, so answers cannot be copied. Each case is a JSON file `{"lesson": "P03.NN", "seed": int, "inputs": {...}, "expected": {...}, "tolerance": {...}}`. Generate new ones with `generate.py` (which uses the reference solutions) and check a learner's implementation with `run.py`. Expected values come from SciPy as the oracle (`scipy.optimize.brentq` and `root` for the root-finding and trim lessons, `scipy.interpolate.CubicSpline`, `scipy.integrate.quad` and `solve_ivp` at rtol 10⁻¹² for the quadrature and ODE lessons, `scipy.linalg.lu_factor`, `cho_factor` and `scipy.sparse.linalg.cg` for the linear-algebra lessons, `scipy.optimize.minimize` for the optimisation lessons, a Gauss–Hermite quadrature of the exact response for the uncertainty lesson) or from a closed form or a manufactured solution where one exists, and the tolerance is set so that a correct from-scratch implementation passes but a Newton step with the derivative of the wrong sign, a Gauss node placed at the panel edge, a Runge–Kutta stage evaluated at the wrong time, a Cholesky that skips the subtraction of earlier columns, a CG with the wrong β, a stencil with an off-by-one at the boundary, or a Richardson extrapolation with the theoretical instead of the observed order does not. Every case that involves a convergence study supplies two or three resolutions and requires the *observed order* to lie within a stated band of the theoretical one, so an implementation that returns the right number on one grid by luck still fails. Anything random inside a case (a random SPD matrix, Monte Carlo samples, a perturbed initial guess) is generated from the case's seed with `numpy.random.default_rng(seed)`, and statistical tolerances are stated with the number of samples that justifies them.

Cases shipped:

- `p03-02-kepler-*.json`: eccentricity e, mean anomaly M (both from the seed, e ∈ [0, 0.95]), a starting guess and a tolerance → the eccentric anomaly E, the number of Newton iterations to the tolerance, and the first three Newton iterates (rtol 1e-12 on E against `brentq`; the iterates must match to 1e-10, so a wrong f′ fails; the error ratios e_{k+1}/e_k² must settle to |f″/(2f′)| at the root within 20%; for e > 0.9 the case also supplies M < 0.1 and requires the implementation to converge from E₀ = π or a safeguarded start).
- `p03-04-quadrature-*.json`: an integrand chosen from a seeded family (the rocket-equation integrand with random m₀, ṁ, v_e; a Gaussian heat pulse; a polynomial of degree 2n − 1), an interval and a point count n → the n-point Gauss–Legendre nodes and weights, the Gauss result, the composite Simpson result at two panel counts, and the observed Simpson order (nodes and weights to 1e-13 against `numpy.polynomial.legendre.leggauss`; the Gauss rule must integrate the degree-(2n − 1) polynomial to 1e-12 and the degree-2n one must *not* be exact; the Simpson observed order must be 4 ± 0.3).
- `p03-05-rk4-*.json`: a linear or mildly nonlinear ODE system (a damped pitch mode with random λ, a forced non-autonomous mode y′ = λy + A sin ωt with a closed form) and two step sizes → the solution at t_end at each step and the observed order (rtol 1e-8 against the closed form or `solve_ivp` at rtol 1e-12; the observed order must be 4 ± 0.2 on the *non-autonomous* problem, so a stage evaluated at the wrong time fails; the free-fall limit f = const must be exact to 1e-13).
- `p03-08-direct-solvers-*.json`: a seeded SPD matrix (random Cholesky factor, n from 5 to 50) and a seeded non-symmetric matrix with a right-hand side → the LU factors with the pivot vector, the Cholesky factor, the solution and the relative residual (factors to rtol 1e-10 against `lu_factor`/`cho_factor` up to the pivoting convention; the residual ‖Ax − b‖/(‖A‖‖x‖) must be below 10 n ε; the Cholesky of a seeded *indefinite* matrix must raise an error at the correct column, not return NaN).
- `p03-09-cg-poisson-*.json`: a grid size N, a seeded smooth right-hand side for the 2-D Poisson problem and a tolerance → the solution, the iteration count and the residual history (solution to rtol 1e-8 against `scipy.sparse.linalg.cg` or a direct solve; the iteration count must be within a factor 1.5 of the reference implementation's and must scale as N^{1.0 ± 0.3} between the two grid sizes supplied; the error A-norm history must be monotone, so a wrong β or a residual recomputed with a sign error fails).
- `p03-14-bfgs-*.json`: a seeded quadratic with condition number between 2 and 10³, and the two-dimensional Rosenbrock function from a seeded start → the minimiser, the iteration count, the final gradient norm and, for the quadratic, the inverse-Hessian approximation after n steps (minimiser to atol 1e-6 against `minimize(method="BFGS")`; on the quadratic with exact line search the method must terminate in at most n + 1 iterations and H_n must match H⁻¹ to 1e-6; the line search must satisfy the Wolfe conditions at every accepted step, which the runner checks from the logged iterates).
- `p03-18-grid-convergence-*.json`: three or four values of a quantity on nested grids generated from a seeded error model C* + C₁h^p + C₂h^{p+1} with p ∈ {1, 2, 4} and a refinement ratio r ∈ {2, 3} → the observed order from each triple, the Richardson extrapolate from the finest pair with the observed and with the theoretical order, and the GCI (observed order to 1e-8, extrapolates to 1e-10; the implementation must report the observed order from *every* consecutive triple, and the case supplies one sequence outside the asymptotic range for which it must flag that extrapolation is not justified).

These are written once the reference solutions for lessons 02, 04, 05, 08, 09, 14 and 18 are merged; `generate.py` then produces them deterministically from a seed. Lessons 11 and 12 are assessed through the mini-project (the manufactured solution *is* the unseen case) and lesson 17 through its seeded Monte Carlo tests, so they carry no separate cases here.
