# Data folder: p09-servo-control

- `prediction.md`: the open-loop guess from the actuator's listing (procedure step 4), then the closed-loop prediction table (step 7) and the redesign prediction (step 10), each with its date and time, written before the measurement it predicts. Corrections are added below, dated; nothing is overwritten.
- `safety_tests.md`: date, firmware version, and the result of the stop, limit, sign and travel-limit tests for every session.
- `calibration.csv`: `quantity,value,unit,method,date` (pack voltage, u16 reading at −45° and +45°, DEG_PER_U16, CENTER_U16, sensor noise in deg, ADC hardware bits, loop period).
- `raw/YYYY-MM-DD_<option>_open_loop.csv`, Option B: `run,t_s,duty_cmd,theta_deg,note`; Option A: `run,t_s,cmd_deg,theta_deg,note`. One row per sample, t_s from the step (negative before it), theta_deg relative to the starting angle, `note` = `measured`.
- `raw/YYYY-MM-DD_<option>_closed_loop.csv`: `run,t_s,ref_deg,theta_deg,duty_cmd,kp,ki,note` (Option A: `cmd_deg` instead of `duty_cmd`), the value in `duty_cmd`/`cmd_deg` being the one applied over the sample starting at t_s.
- `reduced/`: outputs of the analysis script (fits, tables, `servo_feedback_lab.png`). To run `analyse_dataset` on your data, copy the raw files to `reduced/` under the names `motor_open_loop.csv`, `motor_closed_loop.csv`, `servo_open_loop.csv`, `servo_closed_loop.csv` (`MEASURED_FILES` in the code) and set the firmware constants at the top of the module to yours.
- `synthetic/`: **SYNTHETIC data**, written by `write_synthetic_csvs(folder, seed=2026)` in the lesson code from `make_synthetic_dataset(seed=2026)`: a seeded simulation of a bench whose true parameters are written at the top of the code (gear motor K = 540 deg/s per unit duty, τ = 45 ms, dead zone +0.10/−0.11; servo K = 0.95, τ = 60 ms, frame latency 12 ms, slew limit 450 deg/s, dead band 0.5°; potentiometer noise and 12-bit quantisation; the firmware law, limits and one-sample delay of `procedure.md`). Simulations, not measurements, for learners without the kit and for checking the analysis. Every file name contains `synthetic`, each file's first line says `SYNTHETIC DATA ... a simulation, not a measurement`, and every row's `note` column reads `synthetic`. The tests regenerate the files from the seed and check that these copies are byte-identical.
  - `synthetic_motor_open_loop.csv`: `run,t_s,duty_cmd,theta_deg,note`; runs 1–3 are duty steps of 0.30, 0.45 and 0.60 at 100 Hz.
  - `synthetic_motor_closed_loop.csv`: `run,t_s,ref_deg,theta_deg,duty_cmd,kp,ki,note`; runs 1–2 are 15° and 60° steps with Kp = 0.029 duty/deg, run 3 a 15° step with the redesigned Kp = 0.022; dead-zone compensation 0.09, duty limit 0.6.
  - `synthetic_servo_open_loop.csv`: `run,t_s,cmd_deg,theta_deg,note`; runs 1–2 are command steps of 20° and 40° at 50 Hz.
  - `synthetic_servo_closed_loop.csv`: `run,t_s,ref_deg,theta_deg,cmd_deg,kp,ki,note`; runs 1–2 are 20° and 45° steps with Kp = 0.33, Ki = 5.9 1/s, command limit ±60°.

Units are in the column names. Never edit a raw file; fix mistakes in the analysis script and say so in the report. A report that uses anything from `synthetic/` says SYNTHETIC in its title, its summary and every figure, and never calls it a measurement.
